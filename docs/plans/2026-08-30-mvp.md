# aura-overlay MVP Implementation Plan

**Goal:** A resident tray app that rings project windows in their repo colors: automatic for terminals with live aura sessions, hotkey-tagged for everything else.
**Prerequisites:** aura Lane A installed (state.json exists); spike verdicts in `aura/docs/LANE-B.md` (renderer PASS, detection PASS).
**Estimated scope:** 6 steps.

Constraints that bind every step: CLAUDE.md rules 1-8 (contract pinned to aura, state.json read-only, raw Win32 overlays, zero deps, fail silent, under 3% CPU at 10 rings).

---

## Step 1: Scaffold + contract pin
**Files:** repo scaffold (README, CLAUDE.md, ARCHITECTURE, this plan), `src/color.js` copied from aura.
**What:** git init; copy `../aura/src/color.js` byte-identical.
**Verify:** `git -C C:/Users/skf_s/aura-overlay log --oneline` shows the scaffold commit; color.js hashes match: `certutil -hashfile` both copies (or `git hash-object` both) and compare.
**Commit:** `chore: scaffold aura-overlay, pin the color contract`

## Step 2: Renderer core (rings from a file)
**Files:** `src/renderer-win.ps1`
**What:** Grow the spike renderer into a multi-ring host: one window class, a ring registry keyed by target hwnd, 30 ms WM_TIMER tick that (a) reloads `rings.json` when mtime changes and reconciles (create/destroy/recolor), (b) tracks each ring's target (rect move/resize, minimize hide, restore show, target-death destroy). `-RingsFile <path>` parameter so tests use a scratch file. No tray, no hotkeys, no brain yet.
**Verify:** Hand-written rings.json against two scratch windows (Notepad, mspaint): both rings pixel-probe to their exact hex; editing the file live recolors one ring and removes the other within ~1 s; minimize/restore and close behave as in the spike; foreground hwnd unchanged throughout; CPU with 2 rings idle under 1%.
**Commit:** `feat: multi-ring renderer host driven by rings.json`

## Step 3: Brain (identity to rings)
**Files:** `src/brain.js`, `src/detect-win.ps1` (adapted from the aura spike)
**What:** The decision loop from ARCHITECTURE "Data Flow": scan windows, identity ladder (tags -> aura-state terminals minus rainbow-owned -> palette processes -> nothing), `colorsFor`, atomic rings.json write on change. `--once` prints the ring set and exits (testable without the renderer); default mode loops every 2 s. `config.json` defaults written on first run: `{ "paletteProcesses": ["chrome", "slack"] }`.
**Verify:** `node src/brain.js --once` twice, 2 s apart: byte-identical output; the WT window with live sessions maps to the exact frameHex stored in aura state.json; rainbow-owned windows absent from the set; chrome windows present with one shared palette hex; `git diff src/color.js` empty.
**Commit:** `feat: brain identity loop writing rings.json`

## Step 4: Wiring + tray (resident app)
**Files:** `src/renderer-win.ps1` (tray + brain child), `bin/start.js`
**What:** Renderer gains the NotifyIcon (tooltip "aura-overlay", context menu: Quit) and spawns the brain as a child at startup, killing it on quit; Quit destroys all rings then exits the message loop. `bin/start.js` launches the renderer hidden via the Start-Process double-hop and prints the pid; `--stop` posts the renderer's registered quit message (WM_CLOSE to its message window) instead of killing processes.
**Verify:** `node bin/start.js` on the live desktop: rings appear on the expected windows within ~3 s; tray icon present; `node bin/start.js --stop` removes every ring, the tray icon, and BOTH processes (verify by pid); a second start works; no orphan node/powershell from the cycle.
**Commit:** `feat: resident tray app wiring brain + renderer`

## Step 5: Hotkey tagging
**Files:** `src/renderer-win.ps1` (RegisterHotKey), `src/brain.js` (resolve + prune)
**What:** Ctrl+Alt+G tags the foreground window (append unresolved entry to tags.json); Ctrl+Alt+U untags it. Brain resolves a new tag once to the newest aura session's identity (frozen repoId/branch persisted back) and prunes tags whose hwnd/pid pair is gone. Hotkey registration failure (already taken) logs to the local log and continues (rule 6).
**Verify:** Tag a scratch Notepad window: ring appears in the newest session's repo color within one brain cycle; switching work to another repo does NOT change the tag's color (frozen); Ctrl+Alt+U clears it; closing the window prunes the tags.json entry; tags survive a full stop/start.
**Commit:** `feat: hotkey tagging with frozen tag identities`

## Step 6: Soak + ship docs
**Files:** `README.md` (quickstart), `docs/ARCHITECTURE.md` (only if drift), one-line Lane B pointer in aura's README (separate commit in aura).
**What:** Run the full app against the real desktop for 5+ minutes with at least 8 rings (palette temporarily widened via config to reach 8 if needed, then restored); measure both processes' CPU and working set at start and end. Document start, stop, tag keys, config, and the OPT-IN autostart command (schtasks one-liner, documented but NOT registered; registering it is Keith's call).
**Verify:** Combined CPU under 3% sustained; working sets flat (no growth over the soak); zero focus changes attributable to the overlay during the soak; stop leaves no trace. Screenshot of the ringed desktop for the record.
**Commit:** `docs: MVP quickstart + soak results` (aura repo: `docs: point Lane B section at aura-overlay`)
